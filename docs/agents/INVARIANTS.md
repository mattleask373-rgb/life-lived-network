# Hard Product & Agent Invariants (Failure Conditions)

Any change that violates these is a HARD FAILURE and must be rejected or rolled back.

## Product invariants
- CAPABILITY ≠ WILLINGNESS
- CAPABILITY ≠ AVAILABILITY
- JOURNEY ≠ AVAILABILITY
- LIVING IN PLACE ≠ SERVING PLACE
- SELECTING PLACE ≠ TRAVELLING THROUGH PLACE
- UNKNOWN must never become YES / confirmed
- Private / blocked / reported entities must not leak into discovery
- Stale capability must never look current
- Unqualified person must never be presented as qualified (especially regulated categories)
- Quiet result preferred over fabricated result
- No second possibility / matching engine
- Fixtures must never silently become production data
- Raw provider responses are never application truth

## Agent / process invariants
- No autonomous merge to main
- No force-push or published-history rewrite
- No invisible work (every substantive change has a durable task)
- No silent overwrite of another agent’s active non-stale work
- No weakening of tests to hide failures
- No secret exposure (service-role, private keys, OAuth secrets)
- Independent review required before ACCEPTED
- Three failed identical attempts → stop and create diagnosis task (no thrashing)

## Regulated categories (must be verified end-to-end)
mental health, healthcare, childcare, electrical, gas/heating, transport of people, financial advice, legal advice, food for sale, construction, and any other policy-flagged category.

If a candidate appears to match but lacks required qualification, discovery must exclude or clearly caveat; UI must not represent the person as qualified.
