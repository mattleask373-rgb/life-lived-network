# Geographic Discovery Backlog

**State:** DESIGN ONLY until Gate 0 identity and Gate 4 locality privacy are evidenced closed. No public page generation or sitemap expansion is authorized.

## Tier 0 — Do not cross

- [ ] Confirm authoritative Lovable repo + protected non-main sync branch, public hostname/build SHA, live Supabase project and disposable project.
- [ ] Close and independently review the exact local_discovery database boundary; prove all list/detail/matching paths use compatible authenticated authorization.
- [ ] Prove deletion protection and owner-approved publication path.
- [ ] Verify robots, sitemap index, child sitemap shards, canonical tags and private-route noindex on the identified deployed build.
- [ ] Keep Life List, private profiles, messages, private moments, saved places and user-specific journey data out of public outputs.

## Tier 1 — Discovery contracts (prepare, do not publish)

- [ ] Reuse the canonical place hierarchy, route-policy registry, source enumeration, and indexability evaluator. Do not create a parallel place resolver or matching engine.
- [ ] Define a single eligibility record contract: public/published, current, non-demo, provenance present, lawful source/rights cleared, human review complete where required, no block/report/moderation exclusion, and enough factual information to be useful.
- [ ] Keep the current locality indexability gate as the authority until an independently reviewed change: it presently requires at least three genuine eligible records and freshness/provenance/completeness checks. Do not lower it merely to generate more URLs.
- [ ] Create pages only for canonical, validated places with materially distinct, supported content. Empty places must have an honest quiet state, not generated filler or fabricated claims.
- [ ] Establish stable canonical URLs, unique title/description, language/hreflang rules, structured data only for facts actually held, and no misleading aggregate counts.
- [ ] Sitemap generation must be bounded, deterministic, count-complete and fail closed on errors, source caps or inconsistent enumeration.

## Tier 2 — Map-centered page model

- [ ] Locality page is an introduction to the same central map, with selected eligible supply and clear locality hierarchy; it is not a separate discovery engine.
- [ ] Listing, need, offer, moment and journey detail routes each have explicit publication/privacy policy. Private or restricted content is never indexable.
- [ ] Local mode and traveler mode are lenses over the same canonical records, not separate duplicated catalogs.
- [ ] Sparse localities prioritise useful needs, offers, practical services and local knowledge only when real eligible content exists; cities may use filters/clusters but never rank on fabricated popularity.
- [ ] A record's owner statement is labelled as such; no page infers availability, qualifications, trustworthiness, opening hours or demand from unrelated records.

## Tier 3 — Search-intent research (after explicit authorization)

- [ ] Use lawfully accessible public sources and permitted platform tools; record source URL, publisher, publication date, retrieval time, geography, language, method, confidence and usage rights.
- [ ] Separate directly observed facts, third-party reported metrics, hypotheses, unknowns and interview-required questions. Absence of data is not zero demand.
- [ ] Do not scrape private search accounts, messages or personal data, bypass rate limits, purchase data, create accounts, contact people, or spend provider budget without explicit authorization.
- [ ] Research should prioritize actual local need categories and seasonal language variants; do not claim measured search volume where no measurement source exists.
- [ ] Any intent → content recommendation remains a proposal requiring eligibility, source rights, local cultural review and duplicate/thin-content checks before publication.

## Tier 4 — Conversion and retention design

- [ ] Reduce click-to-first-useful-map path; only count a useful result when the record was eligible and visible under the user's actual locality/permission.
- [ ] Measure landing → map → eligible detail → voluntary action → confirmed outcome → return, with consent and minimized data.
- [ ] Avoid infinite feeds, streaks, fear/urgency nudges, inferred vulnerability, hidden ranking, and engagement-maximizing loops.
- [ ] Retention success is repeated voluntary real-world utility, not session duration or time in app.

## Acceptance criteria before any place URL is made indexable

1. Gate 0 and Gate 4 are closed with evidence.
2. Canonical place ID and URL resolve to the same locality.
3. Every concrete claim maps to an eligible current source record or explicitly identified local fact.
4. Route policy, page metadata, links, sitemap and robots agree.
5. A complete source scan is proven within configured caps; otherwise publish no new dynamic URLs for that run.
6. Privacy, cultural quality, accessibility, and low-bandwidth manual QA pass.
7. Human owner authorizes release and live GET verification on the confirmed host.
